Request and response structure

In HTTP/1.1 text notation, a request starts with method, target, and protocol version; a response starts with protocol version and status. Headers follow, then an empty line separates headers from optional content.

HTTP/2 and HTTP/3 encode messages differently; the text examples here teach logical structure rather than describing every protocol's wire format.

Host
Identifies the target host in HTTP/1.1 requests.
Accept
Describes preferred response media types.
Content-Type
Describes the media type of the content being sent.
Authorization
Carries credentials for the chosen authentication scheme.
Location
Identifies a related location, such as a newly created resource.

Reference: MDN — HTTP messages.

JSON representations

JSON expresses objects, arrays, strings, numbers, booleans, and null. Keys are quoted strings; comments and trailing commas are not valid JSON. JSON is a common API format, not a REST requirement.

Define field types, required properties, validation rules, and the meaning of omitted versus null values in your contract. A successful response should return only the information the caller is permitted to see.

Headers answer different questions

Accept: application/json asks for JSON in the response. Content-Type: application/json identifies JSON in the message being sent. Neither replaces authentication or input validation.

References: RFC 8259 — JSON and MDN — Message metadata.
