Methods & Status Codes

Make request intent and response outcomes predictable.

HTTP methods

GET
Retrieve a representation. Do not design it to request state changes.
POST
Ask the target to process supplied content; creating a collection member is one common use.
PUT
Create or replace the target resource's state using the supplied representation.
PATCH
Apply changes described by a patch document. Document the supported media type and update semantics.
DELETE
Remove the target's association with its current functionality; this does not guarantee physical data erasure.

References: RFC 9110 — Methods and RFC 5789 — PATCH.

Safety and idempotency

Safe methods have read-only intended semantics. Logging or metering may still occur. Idempotent means repeating an identical request has the same intended server effect as making it once; response codes can differ.

  • GET is safe and idempotent.
  • PUT and DELETE are idempotent but not safe.
  • POST and PATCH do not generally guarantee idempotency.

A particular PATCH operation can be designed to be idempotent: setting a title to a fixed value differs from incrementing a counter. Concurrent updates may require conditional requests, such as If-Match, to avoid lost updates.

Plan retries explicitly

Do not retry a creation request blindly after a timeout: the server may already have completed it. If your contract supports deduplication keys, document their scope and lifetime.

References: RFC 9110 — Method properties and RFC 5789 — PATCH semantics.

Common status codes

Families distinguish informational responses (1xx), success (2xx), redirection (3xx), client errors (4xx), and server errors (5xx). Choose a status reflecting the actual outcome.

200 OK

Successful request; content depends on the method.

201 Created

One or more resources created; commonly include Location for the new resource.

204 No Content

Successful request with no response content.

400 Bad Request

Request cannot be processed because of a client error.

401 Unauthorized

Valid authentication credentials are missing; includes a WWW-Authenticate challenge.

403 Forbidden

Server understands but refuses the request.

404 Not Found

Resource unavailable or its existence is not disclosed.

409 Conflict

Request conflicts with current resource state.

422 Unprocessable Content

Content type and syntax understood, but instructions cannot be processed.

429 Too Many Requests

Client has exceeded a request limit.

500 Internal Server Error

Unexpected server condition prevented completion.

503 Service Unavailable

Temporary overload or maintenance prevents service.

Reference: MDN — HTTP response status codes.
